S2-R01 — Medium — Native asset paths bypass workspace-aware resolution.
Locations: app.go:37, explain.go:122, preview.go:31, preview.go:65.
config.path understands workspace://, but the separate app.resolve understands
only repo://, absolute paths, and declaring-relative paths. SourcePipeline's
normalization.project, route.input.config, and preview example/expectation
references go through app.resolve, without the selected workspace.
Consequently, a supported local model/config declared as workspace://models or
workspace://collector.yaml fails lookup even when a binding explicitly selects
the workspace containing those files. Without a selected workspace, the URI is
converted into a declaring-relative workspace:/... filesystem path instead of
remaining symbolic. This violates S2-C and PIPE-005/AC-005.
Correction: use one path resolver with explicit project/workspace/declaring
context throughout static asset inspection and native preview. Keep unresolved
workspace URIs symbolic and do not attempt filesystem access through a fabricated
relative path. Cover selected workspaces outside the clone and unresolved static
explanation.

S2-R02 — Medium — Caller-relative CLI workspaces are used before normalization.
Locations: resolve.go:156, resolve.go:238, app.go:111, app.go:134.
Select retains c.Workspace verbatim and uses it to resolve binding definitions.
For --workspace relative-dir plus a binding definition workspace://source.yaml,
it returns a relative selection.Definition. run converts its positional
definition to an absolute path, then rejects the selection as a binding-definition
mismatch. Its later workspace normalization cannot repair this earlier comparison.
explain never normalizes the CLI workspace at all. Workspace-derived model/storage
values can therefore remain relative and later receive the wrong declaring-directory
prefix. The existing tests use absolute selected workspace paths.
Correction: normalize explicit CLI workspace selectors relative to the caller
before resolving binding definitions, workspace documents, and their origins.
Add public CLI coverage for a relative CLI override of a file-relative binding workspace.

S2-R03 — Medium — Runtime checksum failures become optional capability success.
Locations: preview.go:28, dependencies.go:46, explain.go:196.
Every verifyRuntime error returns preview code 3, including a verified collector/
Python checksum mismatch. explain treats code 3 as an unavailable optional
capability, yielding default exit 0 or strict exit 3.
Execution remains blocked, but the integrity failure is incorrectly reported as
optional unavailability. The accepted S2 contract requires integrity failures to
return 4; the existing tampered-runtime test covers run, not preview.
Correction: distinguish missing/unqualified runtime capability from invalid
runtime identity, preferably through a typed integrity error. Preserve missing-
runtime default/strict behavior while testing checksum mismatch under both explain
modes. A test can alter the copied receipt rather than the shared installed binary.

S2-R04 — Medium — Level 2 invents the local tracer's graph for unsupported outputs.
Location: explain.go:142.
For every selected route, level 2 constructs source_staging and api_activity stages
and their SQL filenames, independent of r.Models. A valid declaration whose
normalized output is named authentication still receives a declared api_activity
stage, although report.Routes names the actual output.
Level 3 correctly refuses an unsupported model selection, but the cumulative
report already contains a false declared graph. S2-A and PIPE-024/AC-024 require
named outputs and explicit unavailable evidence for unknown dynamic stages.
Correction: emit the qualified tracer topology only for a matching adapter.
Other declared outputs should be represented honestly, with unavailable topology/
native references where no adapter can establish them. Test an unsupported named
output at levels 2 and 3.

S2-R05 — Medium — Coverage descriptions are fixed to api-read for explicit examples.
Locations: preview.go:167, inspect_preview.py:126.
Every successful preview reports the same unobserved branches: fractional time,
rejects, empty input, and unsupported events. The native sample reasons likewise
say these branches were not established.
This is correct for the registered api-read fixture, but --example PATH --route
local_raw admits other compatible CloudTrail documents. A successful explicit
sample containing a valid fractional timestamp is still reported as not establishing
fractional-time coverage. Unsupported/reject counts can also be present in the run
metadata while the coverage description remains fixed.
Correction: derive coverage descriptions from the executed example and native
results, or explicitly scope fixed coverage claims to the registered fixture.
Keep source-derived coverage information in the stable semantic report. Test an
explicit example that actually observes a previously unsampled branch.
